# Pack: frappe (Frappe / ERPNext apps)

Use with the official skills `frappe-app-dev` (writing) and `frappe-code-review` (reviewing).
Codes are cited in reviews. [CI] = checked on changed files by `.ai/check_antipatterns.sh`.
During kit onboarding, compare every rule with the team's CLAUDE.md and the real code; drop or adapt what does not match.

## Backend
- R-A1 [CI] No frappe.db.commit() outside tasks/ and patches/.
- R-A2 [CI] No raw SQL. Order: get_list/get_doc > qb.get_query(..., ignore_permissions=False) > qb > db.sql with params and a reason.
- R-A3 [CI] No frappe.db.set_value on documents. Use doc.save(); after submit use self.db_set.
- R-A4 No wrapper endpoints for plain CRUD (/api/v2/document does it). A document action = `@frappe.whitelist(methods=["POST"])` method on the controller.
- R-A5 Errors via frappe.throw(_("...")). Never return {"success": False}. Never swallow exceptions.
- R-A6 [CI] Never ignore_permissions=True, flags.ignore_permissions, or set_user("Administrator") to make something work.
- R-A7 Never edit apps/frappe, apps/erpnext, site-packages or node_modules. Extend in this order: Custom Fields/Property Setters
  in code > doc_events > extend_doctype_class > override_doctype_class > override_whitelisted_methods. No monkey-patching.
- R-A8 [CI] `_("Text {0}").format(x)`, never an f-string inside _(). Log with frappe.log_error or frappe.logger, never print.
- R-Q3 qb.get_query in user-facing code passes ignore_permissions=False explicitly (the default is True).
- R-Q7 No queries inside loops. Batch with "in", then map.
- R-E1 Entry points (whitelist, hooks, jobs) stay thin: validate, call controller or service, shape output.
- R-E4 Every whitelisted function: explicit methods=[...], type hints on all parameters, a visible permission check. A function that writes never accepts GET.
- R-M1 [CI] Money with flt(value, precision), never float(); dates with frappe.utils, never datetime.now().
- R-S1 Custom Fields and Property Setters on ERPNext DocTypes are created in code, never left only in the database.
- DocType JSON is generated by Desk in developer mode; never hand-write a new DocType JSON unless the team does.
- Data changes ship as idempotent patches listed in patches.txt. hooks.py only wires; no logic in it.
- Calls to external services run in background jobs (frappe.enqueue), never inside a request.

## Frontend (Vue SPA inside the app)
- FE-2 [CI] No v-html. Plain text, or DOMPurify with a reason.
- Never compute money in the browser; call the server.
- If the project has a design system or frontend handbook, write its rules into `frontend/` notes during onboarding (from the real docs and code, never from memory).

## Tests
- Every endpoint gets a per-role permission test. Test command: see AGENTS.md "Commands".
